# 应用更新发布指南

本文档描述本项目的**应用内自动更新**体系:托管仓库的分工、`update.json` 的格式、发新版的操作流程,以及应用侧的更新链路与注意事项。

## 一、仓库分工

| 仓库 | 地址 | 内容 |
| --- | --- | --- |
| 代码仓库 | `gitzcs/TVBoxAPP`(分支 `master`) | 全部源码、构建脚本、文档。**不放安装包** |
| 更新仓库 | `gitzcs/TVBoxApp-release`(分支 `main`) | `update.json` + 各版本签名 APK。只服务应用内更新 |

- 本地对应目录:代码在工程根目录;更新仓库克隆在 `update-repo/`(已被主仓库 `.gitignore` 忽略,不会混入代码提交)。
- 更新仓库的 SSH 地址(配合 `~/.ssh/config` 的 `github.com.gitzcs` 别名):`git@github.com.gitzcs:gitzcs/TVBoxApp-release.git`。

## 二、update.json 格式

放在更新仓库根目录,应用按下列字段解析(见 `UpdateInfo.java`):

```json
{
  "versionCode": 2,
  "versionName": "1.1.0",
  "changelog": "1. 第一条更新说明\n2. 第二条更新说明",
  "sha256": "apk 文件的 SHA-256(小写十六进制,可选但强烈建议)",
  "apk": [
    "https://gh-proxy.com/https://raw.githubusercontent.com/gitzcs/TVBoxApp-release/main/apk/TVBoxApp-1.1.0.apk",
    "https://raw.githubusercontent.com/gitzcs/TVBoxApp-release/main/apk/TVBoxApp-1.1.0.apk"
  ]
}
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `versionCode` | 是 | 整数,必须比线上最新版**大**,应用据此判断是否有新版 |
| `versionName` | 否 | 展示用版本名,如 `1.1.0` |
| `changelog` | 否 | 更新说明,`\n` 换行,展示在更新确认弹窗里 |
| `sha256` | 建议 | 下载完成后做完整性校验,不匹配自动换下一个下载地址 |
| `apk` | 是 | 下载地址数组,**按顺序尝试**;镜像在前、官方 raw 兜底 |

## 三、发新版标准流程

以发布 `1.2.0 (versionCode 3)` 为例:

```bash
# 1. 升版本号(编辑 app/build.gradle)
#    versionCode 2 -> 3
#    versionName '1.1.0' -> '1.2.0'
./gradlew.bat :app:assembleJavaRelease        # 2. 编译签名正式包
git add app/build.gradle && git commit -m "版本:1.2.0 (versionCode 3)"

# 3. 更新产物进更新仓库
cp app/build/outputs/apk/java/release/TVBox_release-java.apk update-repo/apk/TVBoxApp-1.2.0.apk
NEW_SHA=$(sha256sum update-repo/apk/TVBoxApp-1.2.0.apk | cut -d' ' -f1)
#    编辑 update-repo/update.json:versionCode=3、versionName、changelog、sha256=$NEW_SHA、apk 文件名
cd update-repo
git add -A && git commit -m "发布:1.2.0 (versionCode 3)" && git push origin main
cd ..

# 4. 推送代码仓库(含版本号提交与文档)
git push origin master
```

推送完成即生效:老用户应用内**24 小时内自动收到提示**,或「设置 → 检查更新」立即收到。

## 四、应用侧更新链路

实现位于 `app/src/main/java/com/github/tvbox/osc/update/`:

1. **检查**:启动 10 秒后静默检查(24 小时节流);「设置 → 检查更新」随时手动触发。检查地址按英文逗号分隔依次尝试,默认值内置为 TVBoxApp-release 的 gh-proxy 镜像 + 官方 raw 两条;设置里长按「检查更新」可自定义,清空恢复默认。
2. **提示**:发现更新弹窗展示版本号、changelog,「立即更新 / 暂不」。
3. **下载**:`apk` 数组内地址依次尝试,进度框显示百分比与已下载/总大小,可取消;先写 `.tmp` 再改名,避免半截包。
4. **校验**:`sha256` 非空时对流式计算摘要并比对,失败自动换下一个地址。
5. **安装**:API 24+ 走 FileProvider(`cache/update.apk`),API 19-23 直接 file:// URI;系统安装器确认后覆盖安装,签名不一致会被系统拒绝。

## 五、注意事项

- **混淆**:release 开启了 R8,`UpdateInfo` 是 Gson 反序列化模型,`proguard-rules.pro` 中已有 keep 规则,**新增 update.json 字段时必须在模型类加字段并确认规则覆盖**(字段被重命名会导致解析静默失败,Debug 包测不出来)。
- **签名**:所有 APK 必须用同一把 `TVBoxApp-release.jks` 签名,签名不一致系统会拒绝覆盖安装。
- **versionCode 只增不减**:回退版本无法通过应用内更新完成。
- **镜像**:gh-proxy 为公共镜像,偶尔限流;`update.json` 与 `apk` 数组都保留了官方直连地址作为兜底。
- 更新仓库里的历史版本 APK 可以保留(供回溯),`update.json` 始终只指向**最新一个**。
