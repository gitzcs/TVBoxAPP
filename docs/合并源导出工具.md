# 合并源导出工具

用项目里真实的扫描 / 解密 / 合并代码（`RepoScanner`、`CodeHostScanner`、`LocalSourceMerger`），
在本机 JVM 上从 GitHub / GitLab / Gitee 找出**当前可用**的配置并生成「合并后的本地源」同格式文件，
供托管到 Gitee 等国内可达位置使用。

## 运行

```bash
gradlew :app:testJavaDebugUnitTest --tests "com.github.tvbox.osc.finder.MergedSourceExportTest"
```

- 无需设备 / 模拟器，直接跑在本机 JVM 上。
- 需要联网；GitHub / Gitee / GitLab 不可达的通道会自动降级并记入报告。

## 产物

| 文件 | 说明 |
| --- | --- |
| `.temp/merged_export/merged_source.json` | 合并后的配置（与 App 内合并本地源同一格式：spider / sites / parses / flags / ads / doh / lives / wallpaper） |
| `.temp/merged_export/report.json` | 本次运行报告：可用源明细（来源平台 / 地址 / 站点数）、失败候选、镜像改写数量 |

两个文件都在 `.temp/` 下（已被 .gitignore 排除），上传到 Gitee 等托管处即可对外使用。

## 与 App 内自动找源的差异

- 验证只做到「取到配置、可解析、sites 合法且非空」；App 内还有播放层验证与定时维护。
- 产物是**此刻**的扫描结果；源站时效性强，建议定期重跑并更新托管副本。

## GitHub 镜像改写

默认把产物里的 GitHub raw 地址（顶层 `spider`、站点 `jar`、字符串 `ext`）改写为
`https://cdn.jsdelivr.net/gh/...`，国内可直连：

- 关闭改写：`gradlew ... -Dexport.mirror=false`
- 改写数量会记录在 `report.json` 的 `mirrorRewrite` 字段
- App 侧另有兜底：jar 下载失败时会自动依次尝试 jsDelivr / raw.gitmirror 镜像
  （见 `ApiConfig.downloadJarWithMirrors`），两层互为补充。

## 托管建议

1. Gitee 新建公开仓库（需实名认证），上传 `merged_source.json`；
2. 配置地址即 `https://gitee.com/<用户名>/<仓库>/raw/<分支>/merged_source.json`；
3. 把该仓库写进 `app/src/main/assets/source_index.json` 的 `gitee.repos` 种子，
   让 App 首次启动优先验证它（国内秒级可达）；
4. 注意平台内容审核风险，仓库说明保持中性。
